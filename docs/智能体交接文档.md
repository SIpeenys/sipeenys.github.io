## 三、技术架构

```
用户写 md → D:\zsbsth（Hexo 源） → git push
  → Cloudflare Pages（连接 GitHub，自动构建，~1 分钟）→ https://zaosibobobo.space
  → GitHub Actions（.github/workflows/deploy-pages.yml）→ GitHub Pages 备份
评论数据 → Supabase 云数据库（独立于 git）
音乐/图片/搜索 → 静态文件（随站点一起构建部署）
```

**核心认知**：
- 博客 = 静态网站，push 时"烧制"好网页
- 评论 = 独立数据库，不走 git
- 一切以 **git push** 为触发点；本地没 push 的改动不会上线

## 四、评论区 + 管理后台（Supabase）

### 架构
- 前端组件：`source/comments/comments.js`（纯 JS + fetch 直连 Supabase REST API，无第三方依赖）
- 注入方式：`themes/butterfly/_config.yml` 的 `inject.bottom`——检测文章页（`#article-container.post-content`）→ 创建评论容器 → 动态加载 comments.js
- 评论区样式：`source/css/butterfly-gray.css` 的 `.sc-*`（颜色用 CSS 变量，跟随亮/暗模式）

### 权限模型（审核模式）
- 建表 SQL：`supabase-schema.sql`（**触发器强制 status='pending'** + 插入放行 + 读取只显示 approved）
- 管理后台：`source/admin/`（`/admin/` 页面 + Supabase Auth 邮箱密码登录）
- 审核：后台登录后按 全部/待审核/已通过/已拒绝 筛选，一键 通过/拒绝/删除

### ⚠️ 管理后台的 Supabase 侧配置（重要！交接后先问用户是否已做）
`/admin/` 要能登录，需用户曾在 Supabase 控制台完成：
1. Authentication → Users → Add user 创建管理员账号（邮箱+密码）
2. SQL Editor 执行仓库根目录 `supabase-admin-policies.sql`（把里面两处 `you@example.com` 换成管理员邮箱）
3. 推荐：Authentication → Settings 关闭 "Allow new users to sign up"（防别人注册账号）
4. `source/admin/admin.js` 顶部 `ADMIN_EMAIL` 填管理员邮箱

若用户说"后台登不进去"，先检查上面这几步是否完成（这不是代码 bug）。

### 评论区调试三板斧（出问题按此排查）
1. curl 直连 Supabase API 看数据是否返回（确认后端）
2. 抓线上 HTML 看注入脚本和容器是否存在（确认前端挂载）
3. 让用户开无痕窗口 Ctrl+Shift+N（排除浏览器缓存）

## 七、日常操作（用户工作流）

1. 写文章：`hexo new 英文名` → 编辑 `source/_posts/xxx.md`（front-matter 写中文标题）
2. 用户喊"push 一下" → **先 `git status`/`git diff` 检查改动 → 确认没问题 → add/commit/push**（push 用后台方式避免超时：`Start-Process cmd /c 'git push > push-log.txt 2>&1'` + 轮询）
3. 改配置 → push → Cloudflare 约 1 分钟上线（**页面即时更新，无缓存延迟**）
4. 评论审核：`/admin/` 网页后台 或 Supabase Table Editor

> ⚠️ 用户不熟悉 git，所有命令代跑；push 前**务必先 `git diff` 检查**，防止误提交（曾发生过用户删文章被误提交）。

## 八、历史踩坑速查（下一位必须知道）

1. **Cloudflare Pages 预设列表没有 Hexo** → Framework preset 选 None，手动填 Build command `npm run build`、Output directory `public`
2. **`xxx.workers.dev` ≠ Pages**：建 Worker 是空壳（404）；静态站要用 Workers & Pages → **Create application → Pages 标签** → Connect to Git
3. **GitHub Pages 有 10 分钟 CDN 缓存**：改 JS 后用户要硬刷新/无痕窗口才看到新效果（已通过 Cloudflare 缓存策略 + JS 版本号参数缓解）
4. **国内下载 ffmpeg 用 npmmirror**（gyan.dev/GitHub 直连都很慢）：`registry.npmmirror.com/-/binary/ffmpeg-static/b6.1.1/ffmpeg-win32-x64.gz`（目录列表是 JSON，用 ConvertFrom-Json 解析）
5. **PowerShell 传中文路径给原生 exe 会乱码**（ffmpeg 转换中文名文件失败）→ 先 `Copy-Item` 成英文临时名再处理
6. **.NET ReadAllText/WriteAllText 不认 PowerShell `cd` 的相对路径** → 必须写绝对路径 `D:\zsbsth\...`
7. **长命令（构建/大文件推送）30s 超时** → 后台运行（Start-Process）+ 日志轮询
8. **vercel.app 国内 DNS 被污染**（face:b00c）——Vercel/CloudBase 方案已放弃
9. **Hexo 时区坑**：permalink 不含日期（现用 `:title/`），否则 CI(UTC) 和本地(+8) URL 不一致
10. **Supabase RLS 调试**：`Prefer: return=representation` 头会让 pending 行回读报 42501，客户端不带此头即可
11. **ogg 格式 Safari 打不开** → 转 mp3（ffmpeg 一条命令）；音乐文件名用英文
